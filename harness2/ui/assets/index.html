    01 / MODEL CONNECTION

    Keep it close to home.

    Local first

    A local llama.cpp server is a simple place to start. Your model runs on your own machine.

    Loads for each run; unloads after grading and reporting, failure, or stop.

    Use full paths to your existing server executable and GGUF file. Your model stays where you keep it.

    Start your local server, then test the connection to discover its models.

    Use your own project and model access. Authentication and model use can incur provider charges.

    For the Codex runner only. The server must support the Responses API. Configure OpenCode and judging separately in Advanced model settings.

    Advanced model settings

    Local connections use the model above for all three stages. Other connections can use separate models for solving, improving, and judging.

    Match the context window configured on the running model server. Context covers the prompt, tool output, and reply; maximum output must be smaller. These settings tell Harness² the available budget. They do not restart or resize the server.

    Keys are saved locally and never displayed here.
